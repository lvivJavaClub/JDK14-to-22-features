JEP 517 · GA

HTTP/3 for the HTTP Client API

QUIC/UDP comes to java.net.http

  • New HttpClient.Version.HTTP_3 constant — opt-in per client or per request Default remains HTTP/2; falls back transparently if server doesn't support HTTP/3
  • Discovery via Alt-Svc header — JVM caches it, next request upgrades automatically
  • New: BodyPublishers.ofFileChannel(FileChannel, start, length) Stream large file uploads without loading the entire file into heap
  • HttpRequest.Builder::timeout now covers full lifecycle including body consumption
JEP 516 · Performance

Ahead-of-Time Object Caching

Project Leyden — cache JVM objects across restarts

  • Cache heap objects (class metadata, strings, reflection data) from a training run Serialized to a shared archive, replayed on next startup
  • Works with any GC — not just G1 (previous limitation removed)
  • Goal: drastically cut time-to-first-request in containerized / serverless environments
  • Pairs with CDS (Class Data Sharing) — next step toward "closed-world" optimization
JEP 522 · Performance

G1: Improve Throughput by Reducing Synchronization

Throughput improvement for write-heavy workloads

  • Adds a second card table to track old-gen → young-gen references during mutator execution
  • Reduces remembered-set scanning overhead during minor GCs
  • Zero configuration — automatic; no flags needed
  • Most visible in allocation-heavy apps (web servers, batch processors)
JEP 524 · 2nd Preview

PEM Encodings of Cryptographic Objects

PEMEncoder / PEMDecoder — finally a clean API

  • Encode/decode keys, certificates, CRLs — one line instead of 15 Before: strip headers → Base64 → EncryptedPrivateKeyInfo → SecretKeyFactory → Cipher → KeyFactory
  • Encrypted keys: PEMEncoder.of().withEncryption(passphrase).encodeToString(key)
  • New in JDK 26: KeyPair encode/decode; PEMRecord → PEM with decode() returning raw bytes
  • EncryptedPrivateKeyInfo.encryptKey() → encrypt(), now accepts DEREncodable
JEP 525 · 6th Preview

Structured Concurrency

Related tasks as one unit of work — no orphaned threads

Built-in Joiners

  • allSuccessfulOrThrow() — all must succeed
  • awaitAllSuccessfulOrThrow() — collect then throw
  • awaitAll() — wait regardless of failures
  • anySuccessfulOrThrow() — first wins
  • allUntil(predicate) — stop on match

Changes in JDK 26

  • allSuccessfulOrThrow() returns List<T> (was Stream<Subtask>)
  • allUntil() returns List<Subtask>
  • anySuccessfulResultOrThrow() → anySuccessfulOrThrow()
  • Joiner gains onTimeout() callback
JEP 526 · 2nd Preview

Lazy Constants

Formerly "Stable Values" — renamed and simplified in JDK 26

  • LazyConstant<T> — initialized at most once, thread-safe, JIT-constant after first use Singleton without Double-Checked Locking boilerplate
  • Map.ofLazy(keys, fn) — per-key lazy init; unused keys are never computed
  • List.ofLazy(size, fn) — per-index lazy init; unaccessed pages never loaded
  • Renamed from StableValue; low-level methods (orElseSet, trySet) removed
JEP 529 · 11th Incubator

Vector API

SIMD operations — still waiting for Project Valhalla

  • Express vector computations that map to CPU SIMD instructions (AVX2, SVE, …)
  • Still incubating because FloatVector objects are heap-allocated — no value types yet Project Valhalla's primitive classes will eliminate the allocation overhead
  • JIT already auto-vectorizes simple scalar loops — so Vector API wins only on complex patterns Multiple source arrays (R/G/B channels), cross-element ops, explicit lane control
  • 11th preview — API is stable; GA blocked solely on Valhalla
JEP 530 · 4th Preview

Primitive Types in Patterns, instanceof, and switch

Primitives as first-class citizens in patterns

  • Primitives in switch expressions — HTTP status ranges, byte flags, … case int n when n >= 200 && n < 300 -> "OK"
  • Precision-fit casts: if (d instanceof int i) — only true if value fits without loss
  • boolean in switch: case true / case false
  • Closes the gap: records, generics, and now primitives all work uniformly in patterns
JEP 500 · Breaking

Prepare to Make Final Mean Final

Closing the setAccessible loophole for final fields

  • Mutating a final field via reflection now issues a WARNING in JDK 26 Future release will throw IllegalAccessException outright
  • New JVM flag: --illegal-final-field-mutation=deny to opt in early
  • New JFR event: jdk.FinalFieldMutation — find culprits without searching logs
  • Records already blocked outright — regular classes are next
JEP 504 · Removal

Remove the Applet API

27 years · deprecated 2017 · removed 2026

  • Removed: java.applet.*, AppletStub, AudioClip, AppletContext
  • Browsers dropped plugin support years ago — no runtime could run applets anyway
  • Not the only removal — Thread.stop() also gone after 27 years of deprecation

Beyond the JEPs

No JEP number, still worth knowing

Thread.stop() removed Deprecated since JDK 1.2 (1998). Use interrupt() instead.
Default heap size: 1/500 of RAM Was 1/64. Containers with 16 GB RAM → 32 MB heap by default (was 256 MB).
Virtual threads — no class-init pinning VTs no longer pin the carrier thread during class initialization.
Unicode 17.0 New scripts, emoji, and code points in Character and regex.
Dark mode for Javadoc Built-in sun/moon toggle in the generated HTML. No more browser extensions or CSS hacks.
